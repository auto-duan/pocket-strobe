# 微光 · Pocket Strobe

纯前端 Vite + React + TypeScript + Tailwind CSS 4（官方 Vite 插件） 手机频闪页面。没有后端，不显示、录制或上传相机画面，不加载外部字体或分析脚本。

在线使用：https://auto-duan.github.io/pocket-strobe/

## 本地运行

需要现代 Node.js（建议 Node 22.12+）。

```sh
npm ci
npm run dev -- --host
```

- 屏幕与后置 LED 共用唯一目标频率：0.1–999 Hz，默认 15 Hz，共用预设 12 / 20 / 30 / 45 / 60 / 70 Hz；切换模式原样保留输入（包括 999.0），没有模式专属限幅。
- 无滑条，使用原生 number 数字输入（移动端小数键盘），拦截字母、指数与非法粘贴与预设；运行中锁定设置。输入草稿是唯一配置来源，不存在隐藏旧值。允许编辑中清空与末尾小数点（原生控件末尾小数点显示依浏览器而定）；失焦及启动时验证。严格拒绝空值、零、负数、非有限值、超范围、超过一位小数、科学计数法、空格、正号与省略整数位的 .1；不静默取整或限幅，显示行内错误并禁止启动。
- 设置页底部固定开始操作栏，预留安全区与内容底部空间；运行时隐藏操作栏。
- 点击开始即可启动，无风险确认勾选或弹窗；默认 15 Hz，始终手动启动、不自动启动。
- 运行时固定边到边覆盖整个网页视口，隐藏设置、标题与警告，仅右上角保留低调紧凑的停止按钮（至少 44px 触控目标，自动聚焦、键盘可操作）。轻触任意位置、Esc、页面隐藏、pagehide 或组件卸载均停止。
- 可选系统全屏与 Wake Lock；不支持或拒绝时降级，不影响停止。仅浏览器系统全屏成功才可能隐藏浏览器栏；网页视口覆盖不代表隐藏浏览器栏。

## 手机手电筒注意

手机通过局域网 HTTP 地址访问通常不能使用相机；请自行配置可信 HTTPS 开发环境。localhost 的安全上下文豁免仅针对设备本机，不代表手机访问电脑 IP 也可用。公开站点使用 GitHub Pages HTTPS 托管；相机权限与 LED 支持仍取决于设备和浏览器。

仅在点击开始后申请后置相机（environment exact），不申请麦克风。检测 getCapabilities().torch。Android Chrome + 支持 LED 的后置相机通常更合适；**iOS 浏览器通常不支持 torch 控制**，请使用屏幕模式。权限拒绝、后置相机缺失、相机占用、能力不支持均给出说明。停止期间未完成的权限请求无法被浏览器 API 取消，但其迟到媒体流会关闭灯并释放全部轨道，绝不重新启动。

LED applyConstraints 串行等待；停止立即取消调度并将关灯排在当前写操作之后，最后停止轨道。浏览器冻结、硬件故障或驱动调用迟迟不返回时，网页无法保证瞬时关灯；必要时关闭页面或从系统关闭相机/手电筒。

## 安全与精度

**闪光可能引发光敏性癫痫、眩晕或其他不适，即使没有既往病史。** 有相关病史请勿使用；避免照射他人、儿童、驾驶场景；任何不适立即停止。低频并不代表无风险。系统减少动态效果偏好会显示额外提醒，页面没有装饰性动画。

Hz 表示目标每秒闪光次数，不是显示 FPS，也不是实测值。屏幕使用 requestAnimationFrame 和单调时间相位，每显示帧最多更新一次，直接写入输出 DOM，避免 React 高频重渲染；跳过错失的边沿，不追赶补发。60 Hz 屏幕理想交替上限 30 Hz；亮暗最短各一帧（约 16.7 ms），15 Hz 理想亮暗各两帧，20 / 24 Hz 等存在量化和混叠，不能保证精确定格。

50% 为目标占空比，不提供虚假的亚帧短脉冲设置。定格清晰度更适合短脉冲专用频闪灯；屏幕只能探索暗处运动物体的定格/慢动作错觉，亮度、物体速度与同步都会影响效果。LED 与屏幕都可设置至 999 Hz，但这只是目标，不是实测或保证值。LED 串行等待每次写入完成，相邻 API 命令实际开始时刻至少相隔 16 ms（不是完成后再等 16 ms）（最多约 63 次状态写入/秒，完整亮暗周期还需两次写入），慢硬件进一步降低速率；不构造高频计时忙循环、不堆积脉冲。定时器、刷新率、LED 驱动、设备负载和省电策略均影响实际频率。慢写入不重叠、不追赶补发脉冲。非精密测量、医疗或求救工具，持续使用会耗电、发热；勿长时间运行。

## 手电筒调度与本机诊断

LED 使用 performance.now() 单调绝对边沿时间网格，不再逐次相对延时累计漂移。过期边沿直接跳过，不补发；写入完成后，选择不早于完成时刻、且距上次 API 实际开始至少 16ms、与上次成功命令相反的网格边沿；恰好完成于边沿仍可使用该边沿（仅 0.0000001ms 浮点容差），绝无完成后额外 16ms 等待，避免高频偶数相位采样导致一直亮。提前的计时器回调重新等待；小幅迟到仍使用当前网格区间，整段过期才跳过。迟到回调若采到相同状态则不重复写入。半周期小于 1ms 时，使用最近的相反网格相位（允许不到两条边沿的迟到）避免整数计时器永久采到同一状态；仍只写一条、不回放积压，开始间隔至少 16ms。目标不变，不代表驱动能按此速率输出；慢设备仍可能出现较长亮暗时段，而不是恢复精准 10Hz。

默认收起的「本机手电筒诊断」约每秒更新一次。只存本机内存，最多保留最近 256 个命令耗时用于 p95；均值/最大值与样本数为整轮累计。记录 API 命令耗时平均/p95/最大值、调度迟到平均/最大值及跳过边沿数。跳过数也包括为避免重复状态、限制请求速率而放弃的未来边沿；不等同于实测漏闪。停止后保留报告，新一轮成功启动手电筒时重置；停止后的迟到命令结果不计入新旧报告。诊断不含清理关灯操作。JSON schemaVersion=2、schedulerVersion=start-grid-v2，导出整轮运行时长和最近 256 条 API 命令 trace：相对本轮起点的 planned/start/end、duration、state、edge，以及该命令之前已省略的 skips/reasons。skippedByReason 将每条省略边沿恰好计入 scheduler（计时器迟到/同相位）、rateLimit（开始间隔保护）、commandBudget（在途调用超出边沿预算）之一；为保持亮暗交替而省略的相位伙伴归属同一原因，不重复计数。累计数包含已决定放弃的未来边沿，故最后命令之后的 skips 可尚未附入下一条 trace；不是光学漏闪计数。观察到迟到/跳过后才提示跟不上目标，不按输入频率单独推断。

手机复测：打开 HTTPS 站点，选择后置手电筒，输入 10Hz，手动开始，约 5–10 秒后点停止（如有不适立即停止）。展开「本机手电筒诊断」，点击「下载诊断 JSON」，将文件连同手机型号、浏览器版本和观察到的亮暗现象提供给维护者。没有自动上传或遥测。**这些是 API 时序，不是测得的 LED 光频**；真实光学频率需外部光电传感器/高速测量设备验证。

确定性模拟：10Hz、串行命令耗时交替 10/90ms 时，前十次命令起点为 0/50/200/250/400/450/600/650/800/850ms；一秒完成 10 条，平均 50ms、p95/最大 90ms，跳过 10 个边沿，无重叠或补发。说明硬件慢时会降为不均匀的低速输出，并非光学 10Hz 保证。999Hz 测试验证每秒不超过 64 条请求、无积压/忙循环。测试还覆盖事件循环迟到、停止中在途命令、报告重置/有界缓冲；浏览器 mock 覆盖默认收起、停止后报告、警告、JSON 导出与 320/390/1280px 布局。

回归模拟（不是 Android 真机复现）：旧逻辑 10Hz/40ms 调用开始为 0/150/300/450ms；修正后 35/40/48ms，以及恰好 50ms 的调用均为 0/50/100/150ms，零跳过。+0.3/+1.9ms 计时器迟到结合 48ms 调用仍无人工跳过。54.8/90ms 超预算调用则为 0/150/300/450ms（交替相位策略），48/54.8ms 混合为 0/50/200/250ms，明确省略而不补发。测试使用独立单调时钟、串行模拟 API，覆盖 999Hz 实际开始间隔、256 条上限、停止/重启隔离、旧故障公式及所有既有输入/屏幕行为。
